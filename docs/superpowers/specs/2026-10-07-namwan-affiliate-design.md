# แบบระบบเว็บโชว์รูมสินค้า Namwan

วันที่: 7 ตุลาคม 2026
สถานะ: เสนอให้ผู้ใช้ตรวจแบบก่อนจัดทำแผนพัฒนา

## เป้าหมายและขอบเขต

สร้างเว็บภาษาไทยสำหรับรวบรวมสินค้า Shopee ที่เจ้าของแนะนำ ผู้เข้าชมค้นหาและเลือกหมวดหมู่สินค้า แล้วกดลิงก์ affiliate ที่เจ้าของใส่ไว้เพื่อไปซื้อบน Shopee รองรับมือถือเป็นหลักและจอคอมพิวเตอร์ โฮสต์บน Netlify และเก็บ source code ใน repository Nitinainon/Namwan

ผู้ใช้ระบุว่าการแก้ไขข้อมูลเบื้องหลังทั้งหมดต้องทำผ่านลิงก์แอดมินและต้องมีรหัสผ่าน และให้ใช้ Supabase โปรเจกต์ https://pmqdgnsypfubuwaebefx.supabase.co สำหรับจัดการข้อมูล หน้าร้านต้องไม่มีลิงก์แอดมินและข้อมูลหลังบ้านเข้าถึงได้เฉพาะผู้มีสิทธิ์แอดมิน สมมติฐานสำหรับรุ่นแรกคือเจ้าของเป็นผู้ดูแลคนเดียว ชื่อ “น้ำหวานคัดให้” เป็นค่าเริ่มต้นที่แก้ได้ในหน้าจัดการ

## หน้าร้านและภาพลักษณ์

ธีมครีม ชมพูพาสเทล และน้ำตาลอ่อน มีภาพแมวประกอบและมุมโค้ง ใช้ตัวอักษรไทยอ่านง่าย ปุ่มเหมาะกับการกดบนมือถือ รองรับแป้นพิมพ์และมีข้อความกำกับฟอร์ม

หน้าร้านประกอบด้วยชื่อเว็บ คำโปรย ช่องค้นหา ตัวกรองหมวดหมู่ สินค้าแนะนำ และรายการสินค้า การ์ดแสดงรูป ชื่อ ราคาโดยประมาณ และเหตุผลที่แนะนำ มีรายละเอียดสินค้าและปุ่มเปิด Shopee ในแท็บใหม่ คงลิงก์ affiliate ที่เจ้าของบันทึกไว้ พร้อมข้อความแจ้งว่าลิงก์บางรายการเป็น affiliate และราคาอาจเปลี่ยนแปลง

ไม่มีการชำระเงินบนเว็บ ไม่มีการสร้างลิงก์ affiliate หรือดึงราคา Shopee อัตโนมัติ เจ้าของกรอกข้อมูลและนำลิงก์ affiliate ของตนเองมาใส่

## ระบบแอดมิน

เข้าทาง /admin โดยไม่มีปุ่มหรือลิงก์นี้ในหน้าร้านและไม่ใส่เส้นทางนี้ใน sitemap กำหนด noindex สำหรับหน้าหลังบ้าน เมื่อยังไม่ได้ยืนยันตัวตน แสดงเฉพาะหน้าเข้าสู่ระบบด้วยอีเมลและรหัสผ่านผ่าน Supabase Auth โหลดหน้าจัดการและข้อมูลหลังบ้านต่อเมื่อ session ถูกต้องและบัญชีอยู่ในรายชื่อแอดมิน บัญชีที่เข้าสู่ระบบได้แต่ไม่มีสิทธิ์แอดมินถูกปฏิเสธ ไม่แสดงฟอร์มจัดการหรือข้อมูลหลังบ้าน การรู้ URL ไม่ให้สิทธิ์เข้าถึง

สร้างบัญชีแอดมินและกำหนดสิทธิ์ผ่าน Supabase Dashboard หรือขั้นตอนติดตั้งที่มีสิทธิ์เท่านั้น ไม่มีหน้าสมัครสมาชิกสาธารณะและปิด public signup บัญชีทั่วไปแก้รายชื่อแอดมินไม่ได้ รหัสผ่านไม่ใส่ใน source code หรือเก็บเป็นข้อมูลหน้าร้าน

หลังเข้าสู่ระบบ จัดการได้ดังนี้:

- สินค้า: เพิ่ม แก้ไข ลบ อัปโหลดหรือเปลี่ยนรูป กรอกชื่อ คำอธิบาย ราคา เหตุผลที่แนะนำ ลิงก์ affiliate หมวดหมู่ สถานะแนะนำ ลำดับ และสถานะเผยแพร่
- หมวดหมู่: เพิ่ม เปลี่ยนชื่อ เรียงลำดับ และลบ โดยต้องย้ายสินค้าที่ใช้หมวดนั้นก่อนลบ
- ข้อมูลหน้าร้าน: ชื่อเว็บ คำโปรย ข้อความแนะนำ แบนเนอร์ และข้อความ affiliate

ฟอร์มมีสถานะกำลังบันทึก ผลสำเร็จ และข้อผิดพลาด เมื่อบันทึกล้มเหลวคงข้อมูลที่กรอกไว้ ยืนยันก่อนลบ และป้องกันการกดบันทึกซ้ำ มีปุ่มออกจากระบบและเปลี่ยนรหัสผ่านสำหรับแอดมินผ่าน Supabase Auth ใช้ข้อความผิดพลาดเข้าสู่ระบบที่ไม่เปิดเผยว่ามีบัญชีอีเมลนั้นหรือไม่

## โครงสร้างและการเก็บข้อมูล

ใช้ React, TypeScript และ Vite สำหรับหน้าเว็บ โฮสต์บน Netlify ใช้ Supabase Postgres เก็บ products, categories, site_settings และ admin_users ใช้ Supabase Storage เก็บรูป และใช้ Supabase Auth ตรวจบัญชีและรหัสผ่าน ข้อมูลไม่ผูกกับการ deploy ของ Netlify

เปิด Row Level Security (RLS) และกำหนด grants กับ policies ทุกตาราง หน้าร้านอ่านเฉพาะสินค้าที่เผยแพร่ หมวดหมู่สาธารณะ และข้อมูลหน้าร้านที่เปิดเผยได้ ทุกการเพิ่ม แก้ไข ลบ และอ่านข้อมูลหลังบ้านต้องตรวจ auth.uid() ว่าอยู่ใน admin_users ที่ควบคุมโดยผู้ติดตั้ง ตรวจสิทธิ์จริงที่ฐานข้อมูลและ Storage แม้เรียก API โดยตรง ใช้ฟังก์ชันตรวจสิทธิ์ที่ไม่เกิด RLS recursion และป้องกันการเปลี่ยนแปลงสิทธิ์โดย browser

หน้าเว็บใช้เฉพาะ Supabase project URL และ publishable key (หรือ legacy anon key) ซึ่งต้องทำงานภายใต้ RLS ไม่ใช้ secret key หรือ service_role key ใน browser หรือไฟล์ที่เผยแพร่ แยกโหลดส่วนหน้าร้านและส่วนแอดมิน ลดการส่งโค้ดหลังบ้านไปให้หน้าร้าน แต่ความปลอดภัยต้องอาศัย Auth และ RLS

ใช้ Supabase SDK จัดการ session และ refresh ตามอายุ token เมื่อออกจากระบบล้าง session และข้อมูลหลังบ้านในแอป การ sign out ปกติไม่ได้ทำให้ access JWT ที่ออกไปแล้วหมดอายุทันที จึงไม่อ้างว่าป้องกัน token เดิมได้ทันที ตั้งอายุ token ให้เหมาะสมและการถอนสิทธิ์ admin_users ต้องทำให้การเขียนถูกปฏิเสธทันทีผ่าน RLS

ตรวจชนิดและขนาดรูปก่อนบันทึก รับ JPEG, PNG และ WebP ตรวจ URL ให้เป็น HTTPS และลิงก์ Shopee ของประเทศไทยหรือโดเมน short link ที่รองรับ ไม่แสดง HTML ที่ผู้ดูแลกรอกเป็น HTML จริง

ข้อมูลมี UUID ถาวรและ revision ตรวจ revision แบบ atomic ก่อนบันทึกเพื่อแจ้งเมื่อข้อมูลเปลี่ยนจากอีกแท็บ ใช้ foreign key ป้องกันลบหมวดหมู่ที่ยังมีสินค้า ตรวจข้อมูลสำคัญด้วย database constraints ควบคู่ฟอร์ม อนุญาตเฉพาะแอดมินอัปโหลด แก้ไข หรือลบรูปผ่าน Storage policies รูปหน้าร้านใช้ public bucket และถือเป็นไฟล์สาธารณะ รวมถึงรูปที่อัปโหลดก่อนเผยแพร่สินค้า จึงไม่ใช้ bucket นี้เก็บข้อมูลลับ

## การเชื่อมต่อและเผยแพร่

จัดเตรียม netlify.toml สำหรับ build และ routing พร้อม SQL migration และคู่มือภาษาไทยสำหรับเชื่อม GitHub กับ Netlify ตั้งค่า VITE_SUPABASE_URL และ VITE_SUPABASE_PUBLISHABLE_KEY ติดตั้งตาราง/RLS/Storage สร้างบัญชีแอดมิน กำหนดรายชื่อแอดมิน ปิด public signup และตั้งค่า Auth URLs ให้ตรงโดเมนจริง การเผยแพร่และติดตั้งฐานข้อมูลจริงขึ้นอยู่กับสิทธิ์บัญชี GitHub, Netlify และ Supabase ที่เข้าถึงได้ URL ของโปรเจกต์อย่างเดียวไม่เพียงพอสำหรับติดตั้งฐานข้อมูล ต้องรายงาน URL เว็บจริงหลัง deploy สำเร็จเท่านั้น

เริ่มด้วยข้อมูลตัวอย่างที่ระบุว่าเป็นตัวอย่าง ไม่มีการอ้างว่าเป็นลิงก์ affiliate จริงของเจ้าของ เจ้าของสามารถลบหรือแทนที่ข้อมูลตัวอย่างทั้งหมดผ่านหน้าแอดมิน

## เกณฑ์ตรวจรับ

- หน้าร้านใช้งานได้บนมือถือโดยไม่มีการเลื่อนแนวนอน และค้นหา/กรองหมวดหมู่ได้
- เมื่อยังไม่เข้าสู่ระบบ ไม่สามารถเพิ่ม แก้ไข ลบ หรืออัปโหลดผ่าน API ได้ แม้เรียก API โดยตรง
- รหัสผ่านผิดเข้าสู่ระบบไม่ได้ บัญชีที่ไม่มีสิทธิ์แอดมินเข้าหลังบ้านหรือเขียนข้อมูลไม่ได้ ออกจากระบบแล้วหน้าเว็บล้าง session และกลับไปหน้าเข้าสู่ระบบ ถอนสิทธิ์แอดมินแล้ว token ที่ยังไม่หมดอายุเขียนข้อมูลไม่ได้
- หน้าร้านไม่มีลิงก์แอดมินและไม่ดึงสินค้าฉบับร่างหรือรายชื่อแอดมิน การเรียก REST และ Storage API โดยตรงต้องผ่านสิทธิ์เดียวกัน
- เพิ่ม แก้ไข ลบสินค้าและจัดการหมวดหมู่ผ่าน /admin ได้ และเปิดจากอีกอุปกรณ์เห็นข้อมูลที่บันทึก
- ข้อมูลคงอยู่หลัง deploy ใหม่ และข้อผิดพลาดการบันทึกไม่ทำให้ข้อมูลเดิมหาย
- ข้อมูลหน้าร้านที่แก้ไขจาก /admin แสดงในหน้าร้าน และลิงก์สินค้าเปิด URL ที่บันทึกไว้
- build ผ่าน ตรวจเส้นทางหลักและสิทธิ์ API รวมถึงพฤติกรรมเมื่อ backend ใช้งานไม่ได้
